# Harbor Design System — Design System

**Version 1.0.2** · Group standard · Namespace `AdpStandard`

A clear, familiar foundation for enterprise portals and everyday operational workflows.

## Sources used

This system was generated by UX Factory from **uxfactory-ui/src/styles/index.css (AgentLens Steel)**. Every value below is that source's, re-measured against WCAG 2.1 AA; values that did not meet AA were darkened while preserving hue, and decorative values were left unchanged.

- **No logo, photography or icon set ships with this system.** Nothing was supplied, and a mark is never reconstructed. Where a logo belongs, the name is set in the brand typeface.
- **The typeface is Inter**, hosted on Google Fonts, in weights 400, 500, 600, 700; the stack falls back to `'Inter', ui-sans-serif, system-ui, sans-serif`. No font file ships; add one under `fonts/` and list it in `tokens.json` `type.fonts` to self-host.
- **Themes:** Light and Dark. `light` is the default; switch with `data-theme="dark"` on a root element.

## Visual foundations

**Colour.** `background` (#f4f6f5) is the canvas; `surface` (#ffffff) raises cards and panels on it and `surface-overlay` lifts menus and dialogs above them. Text is `foreground` and, for anything secondary, `muted-foreground`. `primary` (#2f6690) is the one brand colour: primary buttons, links, active states and the focus ring, with `primary-foreground` on it. `accent` is the tinted fill behind hover and selected states, with `accent-foreground` on it. Controls are bounded by `border` (3:1 against the surfaces); hairlines and dividers use `border-subtle`. The four statuses — success, warning, danger, info — each have a foreground, a tinted background and a border, and mean the same thing in every component. Two accents never meet in one element, and colour is never the only signal.

**Type.** One family, Inter, in 4 weights. The scale runs `h1` 24px/1.25 700, `h2` 20px/1.3 600, `h3` 18px/1.35 600, `body` 14px/1.5 400, `label` 12px/1.3 600, `micro` 11px/1.4 400, `title` 15px/1.4 600, `body-sm` 13px/1.5 400, `caption` 12px/1.45 400, `display` 30px/1.2 700, `eyebrow` 11px/1.3 600. Headings earn size through contrast with the body, not decoration; eyebrows are the only uppercase text.

**Spacing.** One scale: 0px / 4px / 8px / 12px / 16px / 24px / 32px / 48px / 64px / 96px / 128px. Related items sit closer (`space-1` to `space-3`), groups get `space-4` and `space-5`, sections get `space-6` and above. No value outside the scale is used.

**Radius.** `radius-lg` 12px, `radius-md` 8px, `radius-sm` 6px, `radius-xl` 16px, `radius-xs` 2px, `radius-none` 0px, `radius-pill` 999px. Buttons and cards take `radius-md`; inputs and badges `radius-sm`; avatars and status dots `radius-pill`.

**Shadows.** `shadow-card` `0 1px 2px rgb(16 40 55 / 0.08)`; `shadow-focus` `0 0 0 3px rgb(47 102 144 / 0.28)`; `shadow-toast` `0 6px 22px rgb(16 40 55 / 0.16)`; `shadow-raised` `0 4px 12px rgb(16 40 55 / 0.10)`; `shadow-popover` `0 8px 24px rgb(16 40 55 / 0.18)`. Shadows are for light surfaces; in the dark theme depth comes from `surface` over `background` and `surface-overlay` over `surface`. `shadow-focus` is the focus ring on every control and is never removed.

**Controls and layout.** `control-lg` 44px, `control-md` 36px, `control-sm` 32px, `control-xl` 52px, `control-rail` 260px, `control-top-bar` 72px, `control-content-max` 1280px, `control-utility-bar` 48px. Touch targets are `control-lg` or larger.

## Components

| Component | Group | What it is |
|---|---|---|
| Button | Actions | One primary button per view; the rest are outline or ghost. |
| Field | Forms | A label, a control and an optional hint, stacked at space-1. |
| Card | Surfaces | A surface with the card shadow, space-4 padding and a title in h3. |
| Badge | Status | A status chip in one of the four semantic colours, text in label. |
| Table | Data | Headers in title weight, body rows in body, a hairline between rows. |
| Tabs | Navigation | A row of tabs with a hairline below; the active tab carries the primary rule. |

Each component has a live preview and guidelines under `components/<Name>/`. The classes in `components/bundle.css` are plain CSS prefixed `adp-standard-`, so they behave identically in React, Vue, Angular and server-rendered HTML; behaviour (focus trapping, roving tabindex, live regions) comes from the consuming framework's accessible primitives.

## Accessibility

38 meaningful colour pairs were measured against WCAG 2.1 AA — 4.5:1 for text, 3:1 for boundaries — in every theme.

Every pair passes; the lowest ratio is 3.01:1.

## Using the tokens

`tokens.css` is compiled from `tokens.json`: every colour is `var(--<name>)` per theme, spacing `var(--space-4)`, radius `var(--radius-md)`, shadows `var(--shadow-card)`, the family `var(--font-sans)`, and each type style is a class (`.body`, `.h2`). Load `tokens.css` then `components/bundle.css`, and build with the classes or the variables directly. Nothing here depends on UX Factory's prompt builder.
